- Lia endpoints accept only service role/cron or admin/diretor JWT (`requireRealUser`). Why: no public sends or paid AI.
- /vaga updates need the creation HMAC token (`_shared/rhToken.ts`); intake secrets stay log-only until configured. Why: no tampering, no lost leads.
- Every Lia 360dialog send path calls `liaPodeEnviarModoTeste` (`_shared/liaModoTeste.ts`, ia_config.modo_teste/numero_teste) before sending; config read failure blocks. Why: one test lock covers replies, follow-ups, recovery and form bridge.
- WhatsApp unknown-sender free-text naming another city than the sent product stores 'Interesse declarado: …' (`_shared/interesseDeclarado.ts`). Why: lead reflects what the client said.
- Site leads: entry history, declared interest and traffic source come only from DB triggers `trg_site_interesse_bi`/`trg_site_historico_ai` (`fn_site_resumo`), mirrored for display by `src/lib/siteOrigem.ts`; edge functions must not insert a second entry record. Why: every site door (webhook or direct insert) gets the same context once.
- site-events never changes lead stage/owner (only a daily notice); only a new site signup returns a discarded lead to the Roleta. Why: browsing is a signal.
- Reengagement SIM keeps active owned leads: RPCs return `already_active`, webhooks honor it; owner notice closes by X or any button. Why: no wrong redistribution.
- Google Ads visit conversions: once per lead with gclid via `google_ads_conversoes` + `google-ads-conversao-dispatch` (Data Manager API). Why: no duplicates, never blocks visits.
- A site contact for an accepted lead with an owner never removes the broker: trigger trg_site_nao_tira_corretor keeps owner/stage/aceite when motivo_pendencia='fila_ceo_site'. Why: a returning client must stay with the broker who accepted her.
- Site leads arriving via a broker personal link (/c/<profiles.slug_ref>) are inserted already owned/accepted by that active broker in crm-webhook, skipping Roleta; existing leads keep their owner. Why: the link's owner earned the lead.
